The **Eclipse Dataspace Hub** is for developers, platform teams, and anyone planning a dataspace use case. Use it to explore the technology, connect your systems, or run a platform. You do not need to contribute to the Eclipse projects.

> **New to dataspaces?** Start with [A Dataspace Use Case](use-case/) or the [IDSA Rulebook](https://kb.internationaldataspaces.org/external/rulebook/001_Introduction/).

## Component landscape

A dataspace needs a few services that work together under shared rules. Select a box to see what it does and where to learn more.

<CapabilityOverview />

These services can be set up in different ways. An organization can run them itself, share them with others, or use a provider. The two demonstrators below show how.

## Try a demonstrator

A demonstrator is a small dataspace that you can run yourself. JAD and MVD are two separate examples, made for learning and not for production. Pick the one that matches what you want to learn, or see [Demonstrators](demonstrators/) for a comparison.

## Documentation and source repositories

**Concepts and rules.** The [IDSA Rulebook](https://kb.internationaldataspaces.org/external/rulebook/001_Introduction/) explains what a dataspace is and how to create, run, and join one.

**Implementation.** The [EDC documentation for adopters](https://eclipse-edc.github.io/documentation/for-adopters/) helps you evaluate EDC and plan a setup. The Hub gives orientation. For APIs, configuration, releases, and production use, rely on the documentation and repositories of each project.

**Specifications.** For protocol details, read the [Dataspace Protocol (DSP)](https://eclipse-dataspace-protocol-base.github.io/DataspaceProtocol/), the [Decentralized Claims Protocol (DCP)](https://eclipse-dataspace-dcp.github.io/decentralized-claims-protocol/), and [Data Plane Signaling](https://github.com/eclipse-dataplane-signaling/dataplane-signaling).
